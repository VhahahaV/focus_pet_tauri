## 输入计数

macOS 采用一次物理按下计一次的口径：

- 普通按键排除系统自动连发；修饰键区分左右侧，松开不计数。
- 每次鼠标按钮按下计一次，双击计两次；移动、拖动和滚动不再混入点击次数。
- 不再根据空闲时间伪造键盘或鼠标次数；监听不可用时明确显示权限状态。
- 排除带来源进程标记的软件注入事件；锁屏输入不入账。
- “刷新诊断”读取最新采样，不再消耗计数队列。后台采样串行执行，诊断数据随采样更新。
- 退出时补采并保存最后一段输入，避免遗漏两次采样之间的事件。

原生测试构造事件并直接调用生产回调，覆盖双击/三击、自动连发、修饰键松开、两侧 Shift、注入事件和重复排空。这些测试验证软件逻辑，不能替代物理硬件校准。

现场曾尝试按键 20、点击 10 的对照测试，记录到键盘 137、鼠标 0。用户确认当时在操作其他应用，因此此轮对照无效，不算计数失败，也不算精确次数通过。随后用户确认主观上监控已恢复正常；安装版持续采集到了实际输入，权限状态为 `available`。

可重跑固定次数校准：

```sh
npm run verify:input -- --seconds 25 --keys 20 --clicks 10
```

等终端出现 START 后只执行指定物理动作，出现 END 后再操作其他应用。按键 20 次、鼠标 4 次单击加 3 次双击；测试期间不要输入回复。脚本只观察已安装应用，不模拟输入。

## 专注与流畅度

- 工作应用中的安静阅读/思考，不再仅因达到短期无输入阈值就判为走神；仍受离开阈值限制。锁屏、睡眠和娱乐规则保持优先。
- 显式专注会话允许中性活动短暂无输入，娱乐活动仍会触发走神。
- 重启后的连续状态从本次启动重新计时，不把应用退出期间算进连续专注。已在最终安装版确认初始时长为 0 秒。
- 用户原来的灵敏度设置保留。分类属于活动线索，无法证明人的注意力；未识别应用仍可通过现有分类入口校正。
- 删除了每轮采样创建的 AppleScript、shell、ioreg 子进程，改为系统 API。
- 修复没有 Bundle ID 的状态记录不能合并的问题；历史保存合并从平方级查找改为索引查找。
- 只合并相邻且元数据完全相同的历史片段，不填补空档。原始历史 211,666 条合并后约 36,932 条，状态文件约 88.3 MB 降为 11.2 MB。
- 按应用、分类和状态核对升级前所有历史时长，毫秒总量完全一致。实际启动后新记录会继续增长。
- 常规采样约每 2 秒一次，整份历史每 30 秒保存；设置写入、正常退出和睡眠会保存。异常终止可能损失最近一个保存周期的数据。
